# 界面与主题规范

本文记录和鸣 1.5.0 的 Android 与 Windows 共用设计规则，供界面维护与后续平台适配参考。使用方式见[用户指南](user-guide.md)，页面和组件入口见[项目结构](project-structure.md)。

## 设计原则

和鸣以音乐、设备与播放状态为主要内容。页面按功能分组，将高频操作和当前任务放在前面；连接参数、诊断和较少使用的信息默认折叠。说明只在需要判断或处理异常时出现，避免让常驻说明挤占歌曲列表。

四个入口保持稳定：**设备、资源库、正在播放、设置**。手机使用底部导航，宽屏使用侧栏；两端共用中性背景、柔和强调色、标题层级和分组样式，信息密度随宽度调整。界面以清楚、克制和易操作为目标，不使用装饰性重阴影、玻璃叠层或滚动特效。

iPhone、iPad 与 macOS 暂未实现。共用视觉规则为后续适配提供基础，不代表这些平台的安装、音频输出或后台能力已完成。

## 布局与尺寸

以下尺寸为 Flutter 逻辑像素。

| 项目 | 紧凑布局 | 桌面布局 |
| --- | --- | --- |
| 应用壳切换条件 | 窗口宽度小于 860 | 窗口宽度至少 860 |
| 导航 | 底部导航栏 | 侧栏 |
| 页面左右留白 | 20 | 28 |
| 内容宽度 | 使用可用宽度 | 最大 1160 |
| 内容分组圆角 | 20 | 18 |
| 分组内部常规留白 | 18 | 22 |
| 主要分组间距 | 通常 24 | 通常 24 |
| 页面标题 | 24，中等字重 | 24，中等字重 |
| 分组标题 | 16 | 16 |
| 常规正文 | 14–16 | 14–16 |
| 常用按钮最小高度 | 48 | 42 |
| 常用按钮圆角 | 13 | 12 |
| 紧凑图标操作区域 | 至少 44 × 44 | 按桌面控件密度安排 |

移动端使用系统无衬线字体；桌面主题使用微软雅黑，并保留 Noto Sans CJK SC、sans-serif 回退。辅助文字通常为 12–13，不承担唯一的状态或操作提示。

桌面 `DesktopColumns` 在**内容区域**宽度达到 860 时显示主栏与 300 宽次栏，中间留白 24；不足时按主栏、次栏顺序堆叠。这个条件与应用壳的窗口宽度条件分别计算，不能因为出现侧栏就强制显示双列。短窗口下导航和正文仍应可滚动。

### 颜色角色

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 页面背景 | `#F2F3F5` | `#111214` |
| 内容分组 | `#FFFFFF` | `#1C1D20` |
| 主要文字 | `#202124` | `#F1F2F3` |
| 次要文字 | `#666A70` | `#AAADB3` |

页面代码优先使用 `ColorScheme` 的语义角色，避免在组件中重复写颜色值。错误与危险操作使用独立语义色；用户选择主题色不能改变其含义。系统状态栏和导航栏随明暗主题协调配色。

## 页面信息顺序

### 设备

未加入播放组时，优先显示创建播放组、附近播放组和手动加入；本机输出与连接细节放入折叠区。

加入后，先显示当前播放组与主要动作，再显示待处理的加入或接管申请、组内设备和输出控制。较少使用的连接地址放在后面。退出、移出和解散等操作与日常播放操作区分，保留权限和确认规则。

### 资源库

按标题与导入、搜索、分组、类别筛选、播放列表操作、资源列表的顺序组织。搜索框在资源较多时出现。分组和批量管理通过清晰的工具区提供，不将每项管理操作逐行堆叠。

常规资源行展示标题、时长、分组和播放或试听入口；详细格式与路径放入资源详情。未加入播放组时，试听条出现在对应歌曲下方。桌面用行布局提高信息密度，移动端为长标题与较大字号留出换行空间。

### 正在播放

当前歌曲与进度最先显示，然后是本次队列和播放模式。参与设备与连接诊断默认收起；桌面宽屏将其放入次栏，窄屏仍排在队列之后。

上一首、下一首、结束播放、切换资源使用同尺寸图标按钮，保留 Tooltip 和无障碍名称。移动端按钮高 56、等宽；可用宽度不足 216 时改为两列，确保点击区域至少 48。

“下一首生效”只在选择的播放模式尚未生效时提示。准备进度、音频让声、失败和恢复声音入口保持可见，不隐藏在折叠区内。空态与播放态使用一致的内容宽度。

### 设置

按本机名称、外观、资源与播放信息、关于排列。名称编辑保留保存操作、非空校验和 40 字上限。外观包含明暗模式与主题色色板，选择后即时保存；信息类内容默认收起。

桌面将名称与外观置于主栏，信息与关于置于次栏；宽度不足时自然上下排列。设置页不展示没有实际作用的存储位置选择，也不添加未实现的资源维护操作。

## 主题色色板

设置提供 6 种固定主题色。色值由项目选定，配合中性灰背景和浅色或深色内容分组，强调色用于主要按钮、选中状态、导航与播放进度。

| 名称 | 持久化标识 | 种子色 / 浅色主色 |
| --- | --- | --- |
| 松柏绿（默认） | `forest` | `#25664C` |
| 雾霭蓝 | `mist` | `#496780` |
| 丁香紫 | `lilac` | `#716081` |
| 玫瑰灰 | `rose` | `#8A5B6A` |
| 暖沙棕 | `sand` | `#80674B` |
| 石墨灰 | `graphite` | `#59666B` |

设计参考了颜色角色、明暗分别配色和以文字或图标辅助颜色的原则，以及中性灰与强调色的搭配方式。这些是本项目的自定义色板，未直接采用来源中的整套颜色值。[Android 颜色指南](https://developer.android.com/design/ui/mobile/guides/styles/color)、[Radix 色板组合](https://www.radix-ui.com/colors/docs/palette-composition/composing-a-palette)。

浅色主色采用表中的种子值。深色使用更亮的对应色调，松柏绿保留既有明暗颜色；其他颜色通过 `ColorScheme.fromSeed` 生成相关角色。石墨灰使用 `neutral`，其余使用 `tonalSpot`。淡色用于容器，正文和按钮文字仍需保持可读对比。柔和配色是一种风格选择，不代表护眼或减轻疲劳的医学效果。

### 交互与持久化

- 主题色与“跟随系统 / 浅色 / 深色”独立保存，切换其中一项不重置另一项。
- 偏好存储在本机，不随播放组同步。默认模式跟随系统、主题色为松柏绿；缺失或未知颜色值回退为松柏绿。
- 色板同时使用名称、色样、勾选与边框表示选择，不只依赖颜色。按钮带互斥选择语义，支持键盘操作。
- 色板根据可用宽度和文字缩放自动换行。每项最小尺寸为 48 × 80，列数根据文字实际宽度计算，最多 6 列。
- 选择立即生效，不另设保存按钮。主题变化只更新展示，不重建播放会话或原生音频引擎。
- Windows 程序图标、Android 启动器和原生媒体图标保留固定品牌标识；应用内控件随主题色变化。

## 组件与实现入口

| 文件 | 职责 |
| --- | --- |
| [`mobile_components.dart`](../lib/app/mobile_components.dart) | 紧凑布局判断、分组、标题、折叠区和按钮 |
| [`desktop_components.dart`](../lib/app/desktop_components.dart) | 桌面分组、标题、自适应分栏和操作控件 |
| [`theme.dart`](../lib/app/theme.dart) | 共用颜色角色、明暗配色、两种布局密度 |
| [`theme_accent.dart`](../lib/app/theme_accent.dart) | 稳定标识、色名与种子色 |
| [`theme_color_picker.dart`](../lib/app/theme_color_picker.dart) | 两端共用的响应式色板与无障碍状态 |
| [`preferences.dart`](../lib/app/preferences.dart) | 本机偏好读取、回退、保存与变更通知 |
| [`lib/features`](../lib/features) | 四个功能页及其业务操作入口 |

折叠区使用独立 `PageStorageKey`，避免与页面滚动位置共用存储值。布局调整应继续调用原有业务入口，不在页面复制成员权限、队列或音频状态逻辑。

## 界面验证

布局修改需要检查紧凑与宽屏、浅色与深色、长名称、窄窗口和较大字号；确保关键操作可达、没有横向溢出、折叠后切换页面可恢复。图标按钮要验证提示、无障碍名称、点击区域和原操作回调。

主题回归覆盖 6 种色板在两种明暗模式及布局密度下的文字对比、默认值与无效值回退、即时切换、重启持久化，以及与明暗模式的独立性。常规文字与实际背景的对比目标为至少 4.5:1。

现有测试包括 [`app_layout_test.dart`](../test/app_layout_test.dart)、移动端与桌面页面布局测试，以及 [`theme_accent_contrast_test.dart`](../test/theme_accent_contrast_test.dart)、[`settings_theme_accent_test.dart`](../test/settings_theme_accent_test.dart) 等主题测试。命令见[开发指南](build-and-test.md)，实机检查记录见[设备验证](physical-device-validation.md)。界面测试不替代长时网络、后台音频或声学同步测试。
