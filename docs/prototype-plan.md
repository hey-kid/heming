# 验证计划

更新于 2026-11-12，适用于 Windows / Android 1.5 系列及后续迭代。文件名沿用早期规划，内容已更新为当前验证工作；已执行结果见 [设备验证摘要](physical-device-validation.md)。

本计划先补齐两台设备的测量与稳定性，再扩展到四台、六台和更多系统。完成某项计划必须记录实际版本、环境、步骤和结果，不能仅以代码实现或构建成功代替运行验收。

## 验证分层

| 层次 | 主要问题 | 验证方式 |
| --- | --- | --- |
| 自动化逻辑 | 权限、状态转换、旧任务隔离、资源和偏好是否正确 | Flutter 单元 / 组件测试、平台包测试 |
| 原生集成 | 解码、缓冲、校时、输出和停止清理是否工作 | 原生测试、实际设备流和集成入口 |
| 产品流程 | 组队、播放、切项、后台和升级能否连续使用 | 正常 Release 双端操作 |
| 声学测量 | 扬声器实际何时出声，是否随时间漂移 | 多路录音或回环采样，固定设备与输出路径 |

无声素材适合验证长时数据流和状态，不能用于判断实际出声偏差或降音幅度。

## 每次发行的基本检查

1. 运行静态分析及与变更相关的自动测试；涉及控制或公共界面时执行完整 Flutter / 平台回归。
2. 构建 Windows Release 与 Android ARM32 / ARM64 Release，检查版本、必要运行库、APK 架构及签名。
3. 从最终分发产物启动，Android 使用同包覆盖安装，核对资源、分组和偏好保留；测试入口应用不作为发行包。
4. 两端检查设备、资源库、播放和设置，覆盖浅深模式、主题色、长名称、窄窗口和较大字号。
5. 用合成资源完成一次双向主控播放、手动停止与清理；涉及音频和网络时，追加对应场景。

命令与环境见 [构建与测试](build-and-test.md)。Android 安装或自动测试失败时，先检查原因，不通过卸载或清空数据来掩盖升级问题。

## 优先补齐的场景

| 优先级 | 场景 | 需要记录的结果 |
| --- | --- | --- |
| 高 | 两端启动偏差 | 同一测试脉冲的实际出声时间差，多次启动的分布 |
| 高 | 10 / 30 分钟漂移 | 固定采样时刻的声学偏差、累计卡顿、重同步或退出次数 |
| 高 | 最新 Release 双向长测 | 两种主控方向的持续任务、缓冲、错误、停止与资源释放 |
| 高 | 真实中断 | 从机退出是否局部生效，主控中断是否全组停播并要求明确恢复 |
| 中 | Android 后台与焦点 | 多机型、来电、通知、实际外部播放器、熄屏及恢复时序 |
| 中 | Windows 电源与输出 | 最小化、锁屏、关屏、真实休眠、输出热插拔的差异 |
| 中 | 四台 / 六台容量 | 混合设备连续播放、吞吐、缓冲下限、错误和漂移 |
| 中 | 资源与系统压力 | 导入、手动转换、低存储、长文件及取消清理 |
| 后续 | 分发与升级 | 干净系统启动、正式签名、更新及资源保留 |

Apple 平台的验证在具备 Mac 编译和真机环境、完成对应适配后另行规划。

## 声学测量方法

优先使用多通道回环或能够同时采集两端输出的录音设备。使用固定间隔脉冲或其他可重复识别的合成信号，保存原始录音及分析脚本。若通过空气传播录音，记录扬声器与麦克风距离和摆位，区分声音传播时间与设备延迟。

每组测量固定设备型号、系统、输出路径、应用版本与网络条件，分别报告启动偏差、长期偏差、异常次数和重复性。内置扬声器、有线耳机、USB 音频及蓝牙是不同输出路径，应分别测量，不能沿用另一条路径的校准值。

约 5 ms 可作为固定设备与输出路径下的研究目标。取得可复现的声学数据后，才能为相应组合给出精度范围。

## 功能回归要点

- **组队与权限：** 加入须经主控接受，第七台被拒绝；准备、播放和连续切项期间拒绝新成员；待命重新开放加入。
- **任务隔离：** 连续切换至少二十次，结束、退出、移交后迟到的 READY、音频数据和焦点恢复事件不能重启旧任务。
- **队列：** 上一首 / 下一首、点选、顺序 / 随机和自然结束行为一致；模式变更不重启当前曲目，不可用资源按规则跳过。
- **资源：** 导入保留原件且不自动转换；失败、取消和低存储不留下可播放的半成品；分组修改不被异步检测结果覆盖。
- **试听：** 暂停、继续、定位和关闭有效；离库、回后台和入组时停止，不影响同步队列或启动组队服务。
- **焦点：** 普通焦点变化仅影响本机音量因子，不覆盖用户静音或音量；无法可靠判断外部音频停止时保持保守恢复行为。
- **中断：** 区分锁屏、系统真正休眠、网络失联和输出故障；中断后不自动续播已撤销任务。
- **主题与布局：** 六色与明暗模式独立保存，重启后保留；文字和点击区域可用，主题切换不重建播放会话。

## 验证报告格式

| 字段 | 内容 |
| --- | --- |
| 版本 | 源码提交或标签、应用版本、构建模式、是否正常产品入口 |
| 环境 | 设备型号、系统、输出路径、设备数量和网络条件 |
| 素材 | 合成素材生成方法、格式、时长和校验值 |
| 步骤 | 可重复的操作顺序、主控方向、时长和触发事件 |
| 结果 | 预期与实际、通过 / 失败 / 未执行，以及失败发生位置 |
| 证据 | 经脱敏的日志、测量数据、截图或录音；注明采样间隔和时间基准 |
| 边界 | 未测设备、无声测试限制、占位诊断字段及无法确定的结论 |

公开报告使用设备代号，省略个人名称、网络地址、设备序列号和其他应用通知。软件帧位置或异步截图不能替代统一时间基准下的出声测量。
