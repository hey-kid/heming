# 使用指南

和鸣让 Windows 电脑和 Android 手机在同一局域网内组成播放组。一台设备担任**主控**，负责选歌和队列；其余设备跟随播放。电脑和手机均可担任主控。

## 安装与首次启动

Windows 便携包需要完整解压，运行目录中的 `heming.exe`；不要单独移动 EXE。应用默认在主屏幕可用区域居中打开。

Android 支持 Android 8.0 及以上，当前构建包含 ARM32 / ARM64。通过系统安装器安装，同一签名的更新包可覆盖安装，避免卸载造成资源库丢失。当前包仍使用开发签名；安装失败时按设备正常流程处理，不通过卸载或清数据强行重试。

源码仓库不提交构建产物，安装包以实际 Release 附件为准；也可以[从源码构建](build-and-test.md)。

## 连接设备

1. 将所有设备接入同一局域网。
2. 主控在“设备”页点击“创建播放组”。
3. 其他设备在“附近播放组”中申请加入，主控接受申请。
4. 确认成员后，再选择资源开始播放。

每组最多六台设备，包含主控。准备和播放期间不接受新成员，结束后可以继续加入。

自动发现不可用时，使用“输入地址加入”，填写主控页面显示的可达连接地址。访客网络、不同网段或路由器客户端隔离可能阻止连接；手动地址只能绕过发现步骤，不能绕过网络隔离。

## 导入与转换

点击资源库的“导入资源”。导入保留原始格式，不自动转换；检测后显示可播放、待转换或错误状态。

同步播放要求 FLAC、48 kHz、16-bit、双声道。符合规格且完整可解码的文件可直接播放，其他支持的资源需点击“转换”，生成独立播放副本，原件保留。

直接解码支持 WAV、MP3、FLAC；额外格式和视频音轨依赖系统解码能力。同样扩展名的文件可能使用不同编码，受保护或损坏的资源不保证能够处理。只想听一下时，可以使用本机试听。

## 分组与队列

通过分组菜单创建、重命名或删除单层分组，使用批量管理移动资源，并调整组内顺序。删除分组只将其中资源归为未分组，不删除文件。

- 点击分组内歌曲，从该歌曲开始播放整个分组的可用队列。
- 点击未分组歌曲，只播放这一条。
- 点击“播放此列表”，将当前列表作为队列。
- 队列跳过未达到播放规格的资源，并按启动时的列表快照运行。

默认顺序播放。切换随机／顺序后，从**下一首**开始应用，当前歌曲继续。主控可以上一首、下一首或点选曲目；播放完列表后结束，不自动无限循环。

## 同步播放与本机试听

| 行为 | 播放组同步播放 | 未组队本机试听 |
| --- | --- | --- |
| 输出 | 播放组中的参与设备 | 当前设备 |
| 暂停与继续 | 不提供 | 支持 |
| 拖动进度 | 不提供 | 支持 |
| 切歌 | 主控通过队列操作 | 选择另一条试听资源 |
| 离开资源库 | 继续 | 停止试听 |
| 回到后台 | 已开始的播放由平台机制维持 | 停止试听 |

未组队点击资源行“试听”，播放条出现在该资源下方。WAV / MP3 / FLAC 可直接试听原件，其他格式可使用已有播放副本；试听不自动转换。创建或加入播放组会先停止试听。

## 后台、锁屏与其他音频

已开始的组队播放可以在回桌面、关屏或锁屏后继续。Android 通过媒体前台服务维持播放，并向通知栏与系统媒体会话提供曲名、进度和停止操作；卡片呈现方式因系统和厂商而异。

其他应用占用音频时，和鸣可临时降低或静音本机输出，时间轴继续，不覆盖用户自己设置的音量。外部播放结束后，在系统信息可靠时恢复；无法判断时，可使用“恢复本机声音”。

系统真正休眠、强行结束应用、输出变化、断网或缓冲耗尽仍可能停止播放。Android 从后台待命首次启动新播放可能受系统限制，此时需先回到应用前台。实际经过哪些验证见[验证摘要](physical-device-validation.md)。

## 主控与本机设置

主控可以审批加入、管理成员和批准成员的接管申请。移交停止全组播放并清空旧缓存，新主控需重新选择资源。

音量、静音和声道属于本机输出设置。设备名称、外观偏好也在本机保存，不因加入播放组而统一覆盖。

进入“设置 → 外观”选择跟随系统、浅色或深色；下方提供松柏绿、雾霭蓝、丁香紫、玫瑰灰、暖沙棕、石墨灰六种主题色。

点击主题色立即生效并自动保存，重启后保留。颜色与明暗模式独立，默认松柏绿。系统桌面的应用图标仍为固定品牌标识。

## 常见问题

**为什么提示缓冲耗尽？**

当前任务没有及时获得足够音频。检查局域网连接、主控状态和网络负载；如能复现，按[贡献指南](../CONTRIBUTING.md)记录平台、主控角色、发生阶段和错误文字。单次界面进度差不能用来测量声学延迟。

**为什么视频可以导入，却不能转换？**

导入只保存原件，后续解码受系统支持的容器和编码限制。查看资源状态中的具体原因；受保护或损坏的文件不保证能够处理。

**是否保证所有扬声器精确同步到 5 ms？**

没有。约 5 ms 是研究目标，软件状态和静音传输测试不能代替真实扬声器录音或回环测量。四台、六台混合设备容量同样仍需验证。

**可以连接公网设备或使用 AirPlay 吗？**

当前实现面向可信局域网，不包含公网中继、账号服务或 AirPlay，也没有 iPhone / iPad / Mac 客户端。
