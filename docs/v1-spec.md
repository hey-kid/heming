# 产品规格

更新于 2026-11-12，对应 **1.5.0**。文件名保留早期版本命名，本文描述当前产品行为；实现与验证状态分别见 [架构说明](architecture.md) 和 [项目状态](development-status.md)。

## 范围

和鸣把同一局域网内的 Windows 与 Android 设备组成音频播放组。每组最多六台设备，包含一台主控；两种平台均可担任主控或跟随设备。

当前同步的是音频。视频资源可由平台解码器提取音轨，但不提供跨设备视频画面同步。iPhone、iPad、Mac 尚未适配。

六台是产品逻辑上限，实际容量与同步精度仍受设备、输出路径和网络影响。约 5 ms 是待测研究目标，不是当前性能承诺。

## 术语与角色

| 名称 | 含义 |
| --- | --- |
| 主控（master） | 创建播放组、审批加入、选择本机资源和控制全组播放 |
| 跟随设备（slave） | 接收主控音频，按照共同时间播放，可申请接管主控 |
| 待命 | 已连接，当前没有准备或播放任务 |
| 就绪 | 本轮资源、输出和校时已准备完成，等待共同开始时间 |
| 会话 | 一次有效的组内主控关系；移交后建立新会话 |
| 播放任务 | 一首资源的一次同步准备和播放；切项创建新任务 |

## 播放组与主控

- 通过附近播放组或主控地址申请加入，由主控明确接受；只有组内成员可以申请接管。
- 待命允许加入。从开始准备音频起锁定成员，缓冲、预约开始、播放和连续切项期间禁止加入。
- 主控移交会停止全组并清除旧缓存，回到待命；正常移交保留成员及各自输出设置。
- 新主控从自己的资源库选择资源，不接续旧曲目进度，也不迁移对方整个资源库。
- 旧会话或旧任务的迟到指令、就绪消息和音频数据不能重新触发播放。
- 主控突然失联时不自动无缝选主。设备在连接断开或心跳超时后停止旧播放，提示重新建组。
- 跟随设备可以主动退出；主控解散播放组时结束全组会话。

## 资源库

### 导入与转换

导入把文件原样复制到应用管理目录，保留来源格式和内容，不修改用户源文件。导入只检测元数据和音频规格，不自动转码，也不以扩展名替代内容检查。

同步播放使用 **FLAC / 48,000 Hz / 16-bit / 双声道** 播放版本。已经符合规格且可完整解码的 FLAC 直接使用；其他受支持资源须明确点击“转换”。局域网传输使用解码后的同规格 PCM，各设备可按硬件需要做输出采样率转换和漂移修正。

| 资源状态 | 可用操作 | 可进入同步队列 |
| --- | --- | --- |
| 检测中 | 等待检测结果 | 否 |
| 待转换 | 手动转换 | 否 |
| 转换中 | 查看进度、取消 | 否 |
| 可播放 | 播放或加入队列 | 是 |
| 转换失败 | 查看原因、重试 | 否 |
| 文件不可用或无法解码 | 查看原因、重新导入或处理文件 | 否 |

转换使用单任务队列，生成独立播放副本，并在完成后重新检查规格和可解码性。失败、取消或空间不足时保留原件，未完成输出不能进入可播放状态。FLAC 编码无损并不意味着重采样、位深转换或声道转换后与源文件逐位相同；有损源转为 FLAC 也不会恢复已损失的信息。

### 分组

- 每首资源最多属于一个本地分组；支持创建、重命名、删除、批量移动和组内排序。
- 删除分组只把其中资源归入“未分组”，不删除音频。
- 检测和转换异步完成时保留用户最新的分组与顺序。
- 分组、资源和主题偏好均保存在本机，不随播放组同步。

## 队列与播放控制

主控与跟随设备显示同一份完整队列和当前项。只有主控可以上一首、下一首、点选切歌、选择顺序 / 随机模式或结束全组播放。

- 默认顺序播放；切换模式从下一首开始生效，当前歌曲继续。
- 随机模式从未播放的曲目中选择，并保留实际播放历史供上一首返回；列表不自动循环。
- 点击分组内歌曲，从该曲目开始播放整个分组；“播放本组”从组首开始，不受搜索结果缩减。
- 未分组歌曲单独点击播放时，队列只有这一首。开始后使用固定队列快照，后续分组和排序编辑不会改写本轮队列。
- 启动队列时跳过尚未就绪资源；每次切项前再次检查文件，失效条目继续跳过。全部不可播放时保持待命并提示原因。
- 直接选择不可播放条目只提示处理方式，不中断正在播放的有效资源。
- 列表完成或明确结束后回到待命，重新允许成员加入；连续切项期间仍锁定成员。

每次切项都重新执行同步准备，允许曲间等待。同步播放不提供暂停续播、拖动进度、快进、快退、无缝连播或交叉淡入淡出；进度条仅用于查看。

## 本机临时试听

未组队且未申请加入时，可以在资源库试听单条音频，播放条显示在对应资源下方，支持暂停、继续、拖动进度和关闭。试听直接使用可解码的 WAV / MP3 / FLAC 原件，或已有转换副本，不自动转换。

离开资源库、条目被筛选隐藏、应用回后台、创建或加入播放组前会停止试听。试听不创建同步播放组，不改变同步队列，也不启用组队播放的前台服务和媒体通知。

## 同步准备与输出

1. 主控验证目标资源并创建新任务，锁定本轮参与成员。
2. 停止旧任务，清除旧缓冲，各端准备目标资源开头约五秒 PCM；短资源准备到结尾。
3. 各端完成输出初始化、缓冲和校时后报告就绪。
4. 主控安排未来的共同开始时间，所有参与设备到点播放。
5. 播放期间持续传输、维持应用缓冲并修正漂移。

五秒是预备的媒体数据长度，不是必须等待五秒。应用缓冲与硬件输出队列分开；结束、切项或退出后清理旧待播内容。

每台设备支持左声道、右声道或完整音轨，以及独立音量和静音。跟随设备退出后其他设备继续，当前不会自动重新分配声道。输出延迟补偿目前仅有原生工程接口，尚无完整用户标定流程。

## 后台、焦点与异常处理

### 后台和音频焦点

已有同步播放在回桌面或锁屏时继续。Android 使用媒体前台服务、媒体会话和播放期运行锁；Windows 使用播放期电源请求。锁屏 / 关屏与系统真正休眠是不同事件。

通知或其他应用占用音频时，本机可临时降音或静音，组内连接和时间轴继续。恢复时跟随当前进度，不重播错过的内容，也不覆盖用户设置的音量、静音或声道。

临时焦点恢复后解除系统施加的降音或静音。永久失焦后，仅在能可靠识别外部播放器结束并满足稳定条件时尝试自动恢复；无法确认时保持静音，播放页提供“恢复本机声音”。实际行为受平台和机型可提供的事件影响。

Android 在后台待命时首次开启新任务可能受系统限制，需要先回到前台；已经开始的播放和连续切项复用运行中的服务。强制停止应用或系统终止进程后，不自动恢复旧任务。

### 系统媒体状态

Android 向通知栏和系统媒体会话提供曲名、时长、进度、准备 / 播放状态及本机角色。切项时更新，结束后移除；通知可停止播放或返回应用，不提供同步播放的暂停或进度跳转。系统可据此显示锁屏媒体卡片，实际样式和行为由系统决定。

### 中断、掉线与超时

| 事件 | 当前处理 |
| --- | --- |
| 跟随设备输出变化、硬件故障、真实休眠或缓冲耗尽 | 本机停止、清缓存并退出，其余设备继续 |
| 主控发生上述真实中断 | 全组停止并清缓存；仍可保持控制连接协调明确重新选主，未经选择不能再播放 |
| 主控连接断开或心跳超时 | 停止旧播放并结束失效连接，提示重新建组 |
| 准备超时 | 结束本次准备，提示重试或移出未就绪设备 |
| 播放期间新加入申请 | 拒绝并提示等待待命状态 |
| 已撤销任务的迟到事件 | 忽略，不恢复旧任务 |

普通音频焦点变化和锁屏不触发真实中断规则。突然断网和进程崩溃依靠连接状态或心跳检测，远端无法瞬时得知所有故障。

## 设置与界面

设置提供本机名称、跟随系统 / 浅色 / 深色、六种主题色以及播放说明。主题色为松柏绿、雾霭蓝、丁香紫、玫瑰灰、暖沙棕和石墨灰；默认松柏绿，点击后立即生效并保存，与明暗模式独立。

Windows 使用侧栏与自适应分栏，启动时在主屏幕工作区居中。移动端使用底部导航；低频信息折叠，播放控制使用带提示和无障碍名称的图标。资源存放在应用数据目录，设置页不展示“本机存储位置”选择项。

界面规范见 [移动与桌面设计](mobile-design.md)，验证方法及未完成场景见 [验证计划](prototype-plan.md)。
