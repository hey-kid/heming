# 设备验证摘要

更新于 2026-11-12。本文记录实际运行过的版本、场景和结论，帮助评估项目成熟度。当前版本为 **Windows / Android 1.5.0+10**，历史结果保留其版本范围。

测试环境包括 Windows x64 电脑和一款华为 Android 10 / API 29 手机，音频经真实局域网传输；USB 用于部署和诊断。Android 界面检查使用 360dp 宽度和 115% 系统字号。ARM32 / ARM64 构建均已检查，但 ARM64 构建通过不等于 ARM64 真机验收。测试媒体使用合成素材；静音测试验证软件状态和数据流，不能证明真实扬声器出声同步。

## 当前版本：1.5.0

| 领域 | 已执行的检查 | 结果及范围 |
| --- | --- | --- |

| Android 构建与安装 | 两种 ARM ABI、必要原生库、APK v2 签名、覆盖安装及实际安装包一致性 | 通过；仍使用开发签名，未卸载或清除数据 |
| Windows 主题色 | 六色色板、蓝色浅深主题、退出再启动后的保存状态 | 通过；主题色和明暗模式独立保存 |

## 传输和持续播放

| 版本 / 入口 | 方向与时长 | 结果 | 测量边界 |
| --- | --- | --- | --- |
| 1.0.0 原生诊断入口 | Windows → Android，1800 秒窗口 | 两端持续消费 PCM；Android 实际 AAudio XRun 为 0，停止和清理通过 | 使用 debug 测试 APK 与独立主机，不能代替最新 Release 长测或声学测量 |
| 1.2.1 原生诊断入口 | Android → Windows，连续 300 秒 | Windows 1504 次采样最低缓冲约 4.638 秒；两端持续消费 PCM，Android 实际 XRun 为 0 | 验证传输与输出流，不测量扬声器延迟 |
| 1.2.1 正常 Release | Android 主控、Windows 跟随，至少 2 分 34 秒 | 两端保持播放；Windows 多次界面采样缓冲约 4.91 秒；手机回桌面及约 49 秒熄屏后仍在组内播放 | 短时产品流程回归，不是长期压力或锁屏卡片样式验收 |

1.2.1 的专项回归重现了 TCP 响应头与 PCM 分开发送产生的等待。合并写入并启用 `TCP_NODELAY` 后，Android 回环的 100 次短块请求由 4404 ms 降为 16 ms。该对照证明等待问题被消除，没有完整复现此前用户断连时的全部网络条件，也不说明所有缓冲耗尽都来自同一原因。

Windows 原生会话集成还验证了主控移交、20 次连续切项和停止清缓存；1.2.0 队列集成覆盖真实 EOF 推进与手动切项。自动化控制结果与两台设备实际出声精度属于不同指标。

## 后台、焦点和系统媒体状态

以下主要对应 1.1.0–1.2.1 的 Android 10 实机记录。

| 场景 | 实际结果 | 尚未涵盖 |
| --- | --- | --- |
| 手机回桌面 / 熄屏 | 手机作为主控或跟随设备时，短时后台与熄屏期间任务、进度和连接继续；播放服务及运行锁保持 | 长时待机、多厂商策略、进程被系统终止 |
| Windows 最小化 | 恢复窗口后继续显示原任务播放进度 | 实际 Windows 锁屏、电源请求查询及休眠恢复 |
| 临时失焦与降音 | 可控焦点测试应用运行期间，和鸣任务继续；结束后恢复 | 静音素材不能量化实际降音幅度 |
| 永久失焦与恢复 | 可控外部播放器占用期间本机静音；对方结束后恢复；失焦期间切项未复活旧任务 | 真实短视频应用、来电及其他机型的完整事件时序 |
| Android 媒体通知 | 曲名、时长、进度和状态更新；点击返回应用，停止后清理会话与服务 | 系统锁屏卡片外观，以及 Android 13 及以上交互布局 |

熄屏观察不等于设备 CPU 真正休眠后仍能执行。测试手机当时没有显示系统锁屏，不能把亮屏返回应用的截图作为锁屏媒体卡片已展示的证据。1.0.0 曾采用熄屏停止的旧规则，该规则已在 1.1.0 调整；旧版停止测试不计入当前后台持续播放验证。

## 尚未验证的关键指标

- 两台真实扬声器的启动偏差，以及 10 / 30 分钟后的声学漂移。约 5 ms 仅为研究目标。
- 四台、六台混合真机持续播放能力和网络拥塞下的稳定性。
- 最新 Release 的双向长测、资源压力、连续运行和内存趋势。
- 更多 Android 系统和厂商、真实来电、蓝牙、耳机插拔、路由器切换以及 Windows 锁屏 / 休眠恢复。
- 用户可操作的输出路径标定和可复现的校准结果。

软件帧位置、校时 RTT、缓冲和进度条是诊断信息，不能单独证明声学同步。Android `hardwareRatePpm` 尚未实现速率估计，Windows `outputUnderruns` 目前是占位计数，不能将其零值解读为测量结果；具体含义见 [音频引擎](audio-engine.md)。

复现入口见 [构建与测试](build-and-test.md)，待补充场景和报告格式见 [验证计划](prototype-plan.md)。
